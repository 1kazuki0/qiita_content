# 何これ？
atcoderを最近やり始めて、遭遇しました。

https://atcoder.jp/contests/abc466/tasks/abc466_c

いままでは、
「入力を全て受け取る → 計算する → 答えを出力する」
という入力が最初に全部渡され、答えを一度出せば終了する問題しか取り組んだことがありませんでした。

せっかくなので解き方を学びました。

# 用語理解

#### インタラクティブな問題とは？
対話型問題とも呼ばれており、一方通行の会話ではなく**会話のように何度もやりとりする**形式の問題です。
「質問を出す → 答えをもらう → 次の質問を考える」を繰り返します。

インタラクティブな問題の解説にあたり、「バッファリング」と「フラッシュ」という言葉も出てくるので先に説明しておきます。

#### バッファリングとは？
まず、「バッファ」とは一時的にモノを溜めておく置き場所のことです。プログラムでいうとメモリ上の置き場。

例えば宅配便で荷物を送るとき
荷物ができるたびに1個ずつ配送を頼むと効率が悪いので、玄関先にいったん積み上げておきある程度溜まってからまとめて発送します。
この「玄関先の積み上げ場所」がバッファ、「溜めてからまとめて送るやり方」がバッファリングです。

プログラミングも同じで`puts` で文字を出力しても、実は1文字ずつすぐ外に送るのではなく、いったんメモリ上の置き場(バッファ)に溜めておき、ある程度溜まってからまとめて送り出す。これをバッファリングといいます。

#### フラッシュとは？
バッファに溜まっているものを「今すぐ全部送り出せ」と強制する操作のことです。
